# Standing, Qualification, and Recognition

{% include gaam-meta.html %}

> This is an informative candidate concept for evaluation. It does not modify GAAM v0.9.0 requirements, schemas, profiles, vocabularies, or conformance semantics.

Future ecosystems need separate predicates for eligibility, standing, admission, qualification, accreditation or recognition, role assignment, authority, transaction authorisation, and execution. A status lifecycle should support applicant, candidate, qualified, active, under-surveillance, remediation-required, suspended, terminated, transition, closed, withdrawn, reinstated, and superseded states.

Implementation evidence must show that a qualified participant can still lack authority for a particular action, and that identity or registry inclusion does not imply operational authorisation.

## Evaluation questions

- Can the current GAAM model represent the concept without ambiguous interpretation?
- Do multiple implementation patterns require the same semantics?
- Is a draft profile, experimental schema, vocabulary, or behavioural vector necessary?
- What privacy, security, affected-party, market, and continuity consequences arise?
- What evidence would justify normative promotion?
